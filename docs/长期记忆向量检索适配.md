# 长期记忆向量检索适配

## 当前实现

- Embedding 供应商通过 `MemoryEmbeddingClient` 隔离；当前实现复用管理端已配置的 Qwen OpenAI-compatible 配置，调用同一服务商的 `/embeddings` 接口。
- 用户 Episode 与有效结构化记忆由后台索引器异步向量化，来源版本变化后重建；索引失败不会阻断原始记忆处理，后续轮询可继续重试。
- MySQL 的 `memory_embeddings` 是权威来源；可选 Qdrant 只保存向量与最小化元数据，由持久化索引任务异步同步，按 `user_id` 和模型过滤后执行 ANN 召回，结果仍进入已有 MySQL 元数据校验和多因子重排。
- Qdrant 未就绪、索引仍待处理或请求失败时，当前用户的召回会回退到 MySQL 精确余弦搜索，确保异步同步期间不会读取不完整 ANN 结果。
- 索引任务批次扫描会跳过已存在的未完成任务；超过单批上限时仍可持续推进，不会因前一批尚未完成而卡在同一批来源。
- 运行时发现 Qdrant 集合丢失时，先清空对应模型的 MySQL ANN 完成标记，再创建集合并排队回填；回填期间逐用户使用 MySQL 回退。
- 管理员可通过 `GET /api/admin/dashboard/memory-vector-index` 查看聚合索引状态，通过 `POST /api/admin/dashboard/memory-vector-index/rebuild` 发起回建；接口不返回任何用户 ID，回建过程使用持久任务队列。
- 若向量功能关闭、供应商不支持或调用失败，Agent 仍使用现有 SQL/词面检索；Knowledge RAG 不参与 Memory RAG 的候选集。
- 删除单条记忆、Episode 或清空用户记忆时，事务内写入 ANN 删除任务，异步删除 Qdrant 副本；关闭个性化后暂停新的向量生成和召回。

## 配置

可用环境变量：

- `MEMORY_VECTOR_ENABLED`：默认 `true`；设为 `false` 可关闭向量索引和向量召回。
- `MEMORY_EMBEDDING_MODEL`：默认 `text-embedding-v3`。
- `MEMORY_EMBEDDING_DIMENSIONS`：默认 `1024`，需要与 Embedding 服务支持的维度及已有索引一致。
- `MEMORY_EMBEDDING_BATCH_SIZE`、`MEMORY_EMBEDDING_POLL_BATCH_SIZE`、`MEMORY_EMBEDDING_POLL_INTERVAL`：控制异步索引速率。
- `MEMORY_EMBEDDING_INDEX_USER_ID`：可选索引范围；默认 `0` 表示不限定账号，设置为正数后，后台只为该 userId 生成向量，适合隔离账号验收或受控回填。
- `MEMORY_VECTOR_RECALL_LIMIT`、`MEMORY_VECTOR_SCAN_LIMIT`：控制召回数量与单用户扫描上限。
- `MEMORY_QDRANT_ENABLED`：默认仅在 Docker Compose 中开启；普通本地运行默认关闭并使用 MySQL 精确检索。
- `MEMORY_QDRANT_URL`、`MEMORY_QDRANT_COLLECTION`：Qdrant 地址和集合名；Compose 使用内部地址 `http://qdrant:6333`，集合维度须与当前 embedding 维度一致。
- `MEMORY_QDRANT_API_KEY`：连接外部受保护 Qdrant 时可配置；项目 Compose 中的 Qdrant 仅接入 backend 专用内部网络，不映射宿主机端口。
- `MEMORY_QDRANT_CONNECT_TIMEOUT`、`MEMORY_QDRANT_READ_TIMEOUT`、`MEMORY_QDRANT_POLL_INTERVAL`、`MEMORY_QDRANT_POLL_BATCH_SIZE`：控制请求超时和异步索引处理节奏。
- `MEMORY_RANKING_VECTOR_SEMANTIC_RATIO`：控制语义分数中向量分数的占比，默认 `0.70`。

开启向量功能后，Episode 摘要/必要载荷、结构化偏好文本以及当前查询会发送到项目已配置的 Qwen 服务商以生成向量。部署方可以通过 `MEMORY_VECTOR_ENABLED=false` 关闭该路径。不得记录原文、API Key 或向量请求体日志。

使用真实外部 Embedding 服务验收时，应先将 `MEMORY_EMBEDDING_INDEX_USER_ID` 限定到仅含合成数据的隔离账号；该设置只限制后台待索引来源，检索仍由认证用户的 userId 强制隔离。验收结束后恢复原有环境配置。

## 当前边界与后续演进

MySQL 精确余弦检索继续作为小规模环境和故障时的回退；Qdrant 通过 `MemoryVectorStoreAdapter` 边界承载较大规模 ANN 检索。队列按用户串行处理并通过租约、指数退避和周期性回填应对重试与进程中断。

集合级别的故障恢复以 MySQL 的 `ann_indexed_at` 为协调标记。回建接口只重置标记并创建持久化 upsert 任务，不直接批量写 Qdrant；后台 Worker 限速执行并在每一阶段保持 MySQL 检索回退。`memory_embeddings(embedding_model, ann_indexed_at, id)` 索引支持持续扫描待回建数据。

Worker 还会按 `MEMORY_QDRANT_CONSISTENCY_CHECK_INTERVAL`（默认 5 分钟）精确比较当前模型的 Qdrant 点数与 MySQL 已标记索引数；仅在没有待处理 upsert 时执行，发现 Qdrant 少点则触发持久化回建。计数检查之外，`MEMORY_QDRANT_IDENTITY_AUDIT_INTERVAL`（默认 5 秒）会按 `MEMORY_QDRANT_IDENTITY_AUDIT_BATCH_SIZE`（默认 500）分页双向核对确定性点 ID 和来源版本：补排队缺失或载荷不匹配的 MySQL 向量，只删除找不到有效 MySQL 来源的 Qdrant 孤儿点。因此，集合总数相等但具体点被替换/错配时也能自动修复，而不触发全模型回建。分页游标仅保存在 Worker 内存中，进程重启后会从头开始审计；瞬时审计异常会延后 30 秒重试。计数或回建遇到暂时性异常时，同样不会因为一次失败长时间跳过检查。

索引模型或维度变化时，记录的模型名与向量维度用于隔离不兼容向量；切换模型后后台会为当前来源生成新版本。旧模型向量可在确认新索引完整后单独清理。

## 万级向量规模与隔离验证

运行 `rtk python scripts/verify_memory_qdrant_scale.py` 可启动独立、无持久卷的 Qdrant 临时容器，以 32,000 条合成 1024 维向量验证当前默认 HNSW 阈值、用户过滤和 Top-20 召回；压测只使用独立集合，不连接应用 MySQL 或主 Qdrant 集合，结束后自动清理临时集合并移除容器。

2026-09-29 本机结果：32,000/32,000 向量进入 HNSW 索引；目标用户过滤返回 20/20 条本用户结果，Top-20 相关命中 20/20；40 次查询往返延迟 p50 4.68 ms、p95 20.37 ms。该结果是本机合成数据基准，不是线上 SLA 或真实用户记忆召回率。初始 12,000 点分散在 8 个 Segment 时尚未触发 HNSW，故规模验证需检查 `indexed_vectors_count`，不能只看总点数超过 10,000。
