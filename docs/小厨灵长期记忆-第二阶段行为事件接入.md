# 小厨灵长期记忆系统：第二阶段行为事件接入

## 1. 本阶段范围

本阶段只把现有业务行为转化为可追踪的 `memory_episodes`，不做 LLM 抽取、偏好合并、画像重建或向量化。

统一入口是 `MemoryBehaviorEpisodeRecorder`。业务模块只提交行为事件和结构化载荷，由 Recorder 转换为第一阶段的 `MemoryEpisodeCommand`。

记忆写入采用 best effort 策略：记忆事件保存失败时记录错误日志，但不回滚用户原本成功的搜索、收藏、烹饪或反馈操作。

## 2. 已接入行为

| 业务入口 | Episode 类型 | 来源类型 | 说明 |
|---|---|---|---|
| 菜谱生成完成后的搜索记录 | `RECIPE_SEARCH` | `SEARCH_LOG` | 记录查询、食材、菜谱结果、餐次和目标 |
| 保存生成菜谱 | `RECIPE_SAVED` | `RECIPE_RECORD` | 记录菜名、搜索上下文和食材 |
| 删除已保存菜谱 | `RECIPE_UNSAVED` | `RECIPE_RECORD` | 保留取消收藏行为，不删除原 Episode |
| 推荐喜欢/不喜欢 | `RECIPE_FEEDBACK` | `RECOMMENDATION_FEEDBACK` | 记录正负反馈和菜谱/食材快照 |
| 清除推荐反馈 | `RECIPE_FEEDBACK` | `RECOMMENDATION_FEEDBACK` | 记录清除动作及原反馈极性 |
| 标记已做 | `RECIPE_FEEDBACK` | `RECOMMENDATION_FEEDBACK` | 记录用户实际烹饪行为 |
| 冰箱入库 | `PANTRY_STOCK_IN` | `PANTRY_OPERATION` | 记录食材、数量、单位、有效期和库存前后数量 |
| 烹饪消耗库存 | `PANTRY_CONSUMED` | `PANTRY_OPERATION` | 记录菜谱、份数和实际扣减项 |
| 撤销冰箱变动 | `PANTRY_OPERATION_REVERSED` | `PANTRY_OPERATION` | 记录原操作与撤销操作的关系 |
| 上传成品菜并获得视觉评价 | `FINISHED_DISH_REVIEW` | `FINISHED_DISH_REVIEW` | 记录整体分数、摘要、菜谱和模型信息 |

## 3. 未接入行为

当前代码中没有发现独立的用户星级评分接口或 `recipe_rating` 业务表，因此没有虚构入口。现阶段使用已有的推荐 `LIKE/DISLIKE` 反馈、`COOKED` 标记和成品菜视觉评价作为可用反馈来源。

## 4. 幂等与追踪

每个 Episode 都包含：

- `userId`
- `sourceType`
- `sourceId`
- `eventId`
- `idempotencyKey`
- `payloadJson`
- `occurredAt`
- `importance`

搜索、保存、反馈、库存操作和成品评价优先使用已有业务记录 ID 生成幂等键。相同业务事件重复投递时，由第一阶段的用户级唯一幂等索引去重。

## 5. 验收重点

- 已登录用户行为可以生成 Episode；匿名搜索不写入个人长期记忆。
- 原业务服务的用户隔离逻辑保持不变。
- 同一业务操作重试不会重复生成 Episode。
- 空标题、空有效期等历史数据不会阻断原业务流程。
- 行为接入失败不会让搜索、收藏、烹饪或反馈接口失败。
- 35 项行为接入定向测试和后端全量测试通过。
