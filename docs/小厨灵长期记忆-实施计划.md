# 小厨灵长期记忆系统：实施计划

日期：2026-09-22

## 分支与阶段规则

每个阶段使用独立分支，完成后执行编译、测试、迁移检查和代码审查，然后暂停等待确认。未得到确认前，不创建下一阶段分支、不开始下一阶段编码。

当前分支：`feature/长期记忆第一阶段`

## 阶段顺序

### 第一阶段：Session/Episode 持久化底座（当前）

目标：让系统能够可靠保存当前任务状态和原始行为事件。

交付：

- `agent_sessions`、`memory_episodes` Flyway 迁移；
- Session/Episode 实体、Mapper、应用服务；
- 用户隔离、幂等键、版本字段、软删除字段；
- H2 迁移、服务单元测试和持久化测试；
- 当前架构分析、总体架构/数据模型和实施计划文档。

不交付：LLM 抽取、向量检索、画像和前端。

### 第二阶段：现有行为事件接入

建议分支：`feature/长期记忆行为事件接入`

将搜索、保存/取消收藏、烹饪、评分反馈、冰箱操作、菜单选择和显式偏好更新适配为 Episode 写入。优先使用 Spring ApplicationEvent，保持未来切换消息队列的边界；每个事件携带 `eventId` 和 `idempotencyKey`。

### 第三阶段：Memory Extraction 与 Tag Normalization

建议分支：`feature/长期记忆抽取归一化`

增加版本化 PromptTemplateManager、MemoryExtractor、MemoryCandidate、CanonicalTag 和显式/隐式来源判定。低置信度高影响偏好进入待确认状态，不静默写入最终画像。

### 第四阶段：Dedup、Merge、Confidence、Decay 与 Conflict

建议分支：`feature/长期记忆合并冲突解析`

实现证据聚合、语义去重接口、配置化置信度、不同 temporalType 的衰减和冲突解析，落地 `memory_items`、`memory_evidence`、`memory_conflicts`。

### 第五阶段：Structured Profile

建议分支：`feature/长期记忆结构化画像`

实现 Profile Consolidation、乐观锁、异步重建、画像读取和用户查看/修改/删除自己的记忆能力。复用已有健康、营养和饮食偏好表作为事实输入，不重复建同义表。

### 第六阶段：Memory RAG、Query Planner 与 Context Builder

建议分支：`feature/长期记忆检索上下文`

先实现 SQL/metadata 召回和多因子重排，再根据部署环境评估向量存储。Memory RAG 与 Knowledge RAG 分离，增加 token budget、压缩、去重和 retrieval trace。

### 第七阶段：Personalized Skill 与 Agent Tool

建议分支：`feature/长期记忆个性化工具`

增加 `search_memory`、`get_user_profile`、`save_episode`、`update_preference`、`get_personalized_skill`、`record_recipe_feedback` 和 `search_user_recipe_history`，通过工具注册表接入，不把调用逻辑塞进 Controller。

### 第八阶段：评测、可观测和 MCP 适配

建议分支：`feature/长期记忆评测可观测`

增加抽取准确率、Recall@K、冲突解析、去重、错误记忆使用率、陈旧记忆使用率和个性化胜率；记录完整决策链；在 Service 稳定后增加 `xiaochuling-memory-mcp` 薄适配层。

## 当前阶段验收标准

1. Flyway 在 H2 和 MySQL 方言下可执行；
2. 相同用户和相同幂等键重复写 Episode 不产生第二条事实；
3. 不同用户无法读取或更新彼此的 Session/Episode；
4. Session 更新使用 version 条件，版本不匹配时不覆盖新状态；
5. Episode 原始载荷和来源字段可追踪；
6. 单元测试、持久化测试和全量 Maven 测试通过；
7. 不修改现有前端和既有业务表。
